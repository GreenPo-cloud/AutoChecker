# AutoChecker

## Система контроля сборки и упаковки заказов

**Назначение документа:** дать руководителю понятное описание системы AutoChecker.

**Версия системы:** 3.14.

---

## 1. Краткое описание

AutoChecker — это рабочее место для контроля сборки и упаковки заказов.

Система показывает состав заказа на дисплее. Сотрудник сканирует каждый товар. Система сразу сравнивает скан с заказом.

AutoChecker выполняет следующие основные задачи:

- проверяет название товара;
- проверяет количество товара;
- показывает недостающие позиции;
- показывает лишние позиции;
- сообщает об ошибке сразу после неправильного скана;
- печатает этикетки, если выбран принтер;
- сохраняет фотографию собранного заказа;
- записывает результат работы и имя сотрудника;
- позволяет продолжить незавершённый заказ.

Система уменьшает количество ручных проверок. Система также создаёт понятную историю каждого заказа.

Краткая схема работы:

```text
Файл заказов → AutoChecker → дисплей → сканирование товаров
              ↓                         ↓
        печать этикетки        проверка количества
              ↓                         ↓
          фотография  ←  завершение заказа → статистика
```

---

## 2. Для чего нужна система

При ручной сборке сотрудник должен одновременно читать заказ, искать товар и считать количество. Этот процесс создаёт риск ошибки.

Наиболее частые ошибки:

- сотрудник берёт неправильный товар;
- сотрудник берёт неправильное количество;
- сотрудник забывает крупную позицию;
- сотрудник добавляет лишнюю позицию;
- сотрудник использует отменённый заказ;
- два сотрудника начинают работу с одним заказом;
- невозможно быстро определить исполнителя;
- невозможно восстановить ход работы после остановки.

AutoChecker контролирует эти операции во время работы. Система не ждёт итоговой проверки. Система сообщает об ошибке сразу.

---

## 3. Состав системы

Одно рабочее место AutoChecker может иметь следующие компоненты:

1. Компьютер с Windows.
2. Сенсорный дисплей AutoChecker.
3. Сканер штрихкодов.
4. Камеру для фотографии заказа.
5. Принтер этикеток.
6. Программу AutoChecker.
7. Файл настроек.
8. Папки заказов, фотографий и статистики.

Камера и принтер не обязательны для основной проверки. Система продолжает проверять товары без этих устройств.

Сканер можно подключить к дисплею. Резервный сканер можно подключить напрямую к компьютеру.

---

## 4. Запуск рабочего места

При запуске программа выполняет автоматическую проверку оборудования.

Программа находит:

- дисплеи AutoChecker;
- камеры AutoChecker;
- доступные USB-принтеры;
- внешние сканеры;
- новые файлы заказов;
- изменения существующих заказов.

Дисплей получает список доступного оборудования. Сотрудник выбирает своё имя, отдел и нужные устройства.

Программа сохраняет последний выбор для каждого дисплея. При следующем запуске дисплей показывает прежние значения.

Одну камеру, один принтер или один внешний сканер нельзя выбрать на двух активных рабочих местах. Это правило предотвращает конфликт оборудования.

---

## 5. Работа сотрудника

### 5.1 Начало работы

Сотрудник выполняет следующие действия:

1. Выбирает своё имя.
2. Выбирает отдел.
3. Выбирает камеру, если камера нужна.
4. Выбирает принтер, если принтер нужен.
5. Выбирает внешний сканер, если сканер нужен.
6. Запускает рабочий процесс.

### 5.2 Сборка заказа

Дисплей показывает номер заказа и список позиций.

Сотрудник сканирует товар. Программа определяет товар и увеличивает собранное количество.

Дисплей показывает новое состояние сразу после скана.

Основные цвета имеют постоянное значение:

- зелёный цвет показывает правильный результат;
- красный цвет показывает ошибку;
- жёлтый цвет показывает предупреждение;
- голубой цвет показывает последнюю изменённую позицию.

Дополнительные цвета можно настроить для отдельных слов или групп товаров.

### 5.3 Завершение заказа

Программа проверяет все позиции и количества.

Система не считает заказ правильным, если есть ошибка или лишняя позиция.

После завершения система может выполнить следующие действия:

- сделать фотографию;
- сохранить результат в статистике;
- напечатать этикетку;
- выдать следующий доступный заказ.

Доступные действия зависят от выбранного отдела.

---

## 6. Режим RETAIL

Режим RETAIL используется для сборки розничных заказов.

### 6.1 Получение заказов

Программа принимает файл PDF или готовый файл `(Order).json`.

Если JSON отсутствует, программа читает PDF и создаёт JSON. Если JSON существует, программа использует готовые данные.

Лаунчер постоянно проверяет папку заказов. Лаунчер автоматически добавляет новую часть `Part N` в текущую статистику.

Сотруднику не нужно перезапускать программу после появления новой части.

### 6.2 Очерёдность заказов

Система использует следующий приоритет:

1. UPS.
2. Packeta.
3. Postal.

Система не выдаёт Packeta или Postal, пока остаётся незавершённый заказ UPS. Отменённый заказ не блокирует очередь.

### 6.3 Проверка товаров

Программа сравнивает скан с каталогом товаров.

Программа поддерживает:

- числовые штрихкоды;
- текстовые коды;
- товары без штрихкода;
- товары Merch;
- бонусные позиции;
- размеры упаковки;
- настраиваемые исключения.

Обычные позиции имеют приоритет перед бонусными позициями. Бонусная позиция закрывается после соответствующей обычной позиции.

### 6.4 Этикетка заказа

Если выбран принтер, система может напечатать этикетку заказа.

Этикетка содержит:

- имя клиента;
- номер заказа;
- тип доставки;
- текущую дату;
- QR-код с номером заказа.

Для заказа STEALTH система использует отдельный макет.

Размер этикетки и смещение печати задаются в `Settings.json`.

### 6.5 Фотография и результат

Система может сделать фотографию автоматически после правильной сборки.

Сотрудник также может сделать фотографию вручную. Статистика различает автоматическую и ручную фотографию.

После автоматической выдачи система может перейти к следующему заказу. Ручная фотография не запускает автоматическую выдачу.

---

## 7. Режим RETAIL_UP

Режим RETAIL_UP используется для упаковки и печати почтовых этикеток.

Сотрудник сканирует номер заказа. Система выполняет следующие проверки:

1. Заказ существует.
2. Заказ собран.
3. Заказ не отменён.
4. Заказ не требует повторной обработки после изменения.

Для UPS и Packeta система находит нужную страницу в файле почтовых этикеток. Затем система печатает только эту страницу.

Для Postal система не печатает почтовую этикетку. Система записывает имя упаковщика и завершает обработку заказа.

Дисплей показывает количество необработанных заказов:

```text
LEFT UPS: 12, Packeta: 7, Postal: 3
```

После каждой упаковки этот статус обновляется на всех активных дисплеях RETAIL_UP.

Система также показывает важные позиции, которые не входят в каталог PRODUCTS. Бонусные позиции в это предупреждение не входят.

Если этикетку печатают повторно, дисплей показывает предупреждение о повторной печати.

---

## 8. Режим B2B

Режим B2B используется для заказов с отдельным форматом PDF.

Сотрудник сканирует номер заказа. Программа находит PDF и перемещает его в папку `B2B/History`.

Для каждого заказа система создаёт отдельную папку. В папке находятся:

- исходный PDF;
- файл прогресса сборки;
- фотографии заказа.

Программа читает таблицу заказа и сопоставляет названия с каталогом.

Если работа остановилась, следующий сотрудник может продолжить заказ. Система загружает сохранённый прогресс.

Файл прогресса показывает имена сотрудников, которые работали с позициями.

В режиме B2B фотографию делает сотрудник. Система не делает автоматическую фотографию после завершения.

---

## 9. Изменение и отмена заказа

Менеджер может изменить заказ после его создания.

Для этого менеджер помещает файл `Change ...pdf` в папку загрузки. Лаунчер обрабатывает файл только один раз.

Система выполняет следующие действия:

1. Читает новый состав заказа.
2. Обновляет JSON заказа.
3. Добавляет отметку `Change` в статистику.
4. Возвращает заказ в работу.
5. Передаёт обновление активным рабочим местам.

Отметка `Cancelled` имеет более высокий приоритет. Отменённый заказ нельзя взять в работу.

После удаления `Cancelled` система снова применяет обычные правила очереди.

---

## 10. Статистика и контроль

AutoChecker сохраняет историю операций.

Статистика может содержать:

- номер заказа;
- трек-номер;
- имя клиента;
- имя сборщика;
- имя упаковщика;
- состояние заказа;
- ручной или автоматический способ создания фотографии;
- отметку отмены;
- отметку изменения.

Система также ведёт статистику сотрудников.

Статистика сотрудника содержит:

- количество завершённых заказов;
- количество ошибок;
- время между сканами;
- медианное время между сканами.

Эти данные помогают найти повторяющиеся проблемы. Эти данные также помогают оценить рабочий процесс без ручного подсчёта.

---

## 11. Совместная работа нескольких рабочих мест

Несколько станций AutoChecker могут работать одновременно.

Система блокирует файл статистики на время изменения. Другой процесс ждёт освобождения файла.

Это правило уменьшает риск потери данных при одновременной работе.

Режим `support: true` подключает вспомогательный компьютер к общим сетевым папкам.

Вспомогательный компьютер использует общие:

- файлы заказов;
- файлы статистики;
- фотографии.

Этот режим позволяет другому отделу временно помочь основной команде.

---

## 12. Защита от обычных сбоев

Система обрабатывает следующие ситуации:

- отключение дисплея;
- повторное подключение дисплея;
- перезапуск дисплея;
- подключение или отключение камеры;
- подключение или отключение принтера;
- подключение или отключение внешнего сканера;
- временную блокировку общего файла;
- незавершённое OCR-распознавание;
- остановку работы до завершения заказа.

Лаунчер постоянно проверяет доступные устройства. После возврата устройства лаунчер снова добавляет его в список.

Если состав камер изменился, система останавливает процессы с камерами. Это действие предотвращает работу с неправильным идентификатором камеры.

---

## 13. Настройка и обновление

Основные настройки находятся в `Settings.json`.

Файл содержит:

- имена сотрудников;
- названия отделов;
- каталог товаров;
- товары Merch;
- исключения;
- фокус камер;
- параметры дисплеев;
- внешние сканеры;
- цвета;
- параметры печати;
- сетевые пути.

Программа проверяет структуру настроек после обновления. Программа добавляет отсутствующие новые разделы и сохраняет существующие данные.

AutoChecker может получать новую версию из GitHub. Обновление также может включать OCR-модуль и макеты этикеток.

Программа может проверить версию прошивки дисплея. При необходимости программа может обновить прошивку через USB.

Уникальный MAC-адрес сохраняет настройки конкретного дисплея после обновления прошивки.

---

## 14. Польза для отдела

AutoChecker даёт отделу следующие преимущества:

- единый порядок сборки;
- проверку товара во время операции;
- проверку количества во время операции;
- быстрое обнаружение ошибки;
- автоматическую печать нужной этикетки;
- историю действий по заказу;
- фотографию результата;
- работу нескольких сотрудников без ручного объединения данных;
- возможность продолжить незавершённый заказ;
- централизованное обновление программы;
- настройку под правила конкретного отдела.

Система делает процесс видимым. Руководитель получает результат, исполнителя и историю заказа в одном рабочем процессе.

---

## 15. Что нужно для внедрения в новом отделе

Перед внедрением нужно получить следующие данные:

1. Примеры файлов заказов.
2. Список товаров и штрихкодов.
3. Правила обработки количества.
4. Список исключений.
5. Требования к фотографиям.
6. Требования к статистике.
7. Модели принтеров и размеры этикеток.
8. Типы сканеров и камер.
9. Путь к общим сетевым папкам.
10. Правила отмены и изменения заказа.

После этого нужно настроить один тестовый участок. Тестовый участок должен работать на реальных заказах под контролем ответственного сотрудника.

После успешной проверки систему можно установить на другие рабочие места.

---

## 16. Ограничения

AutoChecker использует данные из файлов заказов и каталога товаров. Неправильные исходные данные могут дать неправильный результат.

Новый формат PDF требует отдельной настройки парсинга.

Сетевая работа зависит от доступа к общим папкам.

Печать зависит от правильного драйвера и правильного размера бумаги.

AutoChecker помогает сотруднику выполнить проверку. Система не заменяет правила отдела и контроль руководителя.

---

## 17. Основные термины

**Лаунчер** — главная часть программы. Лаунчер находит устройства и запускает рабочие процессы.

**Рабочий процесс** — отдельная работа одного дисплея с одним сотрудником.

**Дисплей AutoChecker** — сенсорный экран для выбора режима и показа состояния заказа.

**Order JSON** — подготовленный файл с составом заказов.

**Label JSON** — файл со связью между трек-номером и страницей почтовой этикетки.

**Статистика** — файл с состоянием заказов и именами сотрудников.

**PRODUCTS** — каталог обычных товаров с проверкой по коду.

**Merch** — каталог дополнительных товаров и мерча.

**Change** — отметка о новом составе существующего заказа.

**Cancelled** — отметка отменённого заказа.

---

## 18. Итог

AutoChecker объединяет получение заказа, проверку товара, печать, фотографию и статистику.

Сотрудник получает простые действия и немедленную обратную связь. Руководитель получает контролируемый процесс и историю результата.

Систему можно адаптировать к другому отделу. Для адаптации нужны примеры документов, каталог товаров и правила нового отдела.
